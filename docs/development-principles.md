# 开发原则

## 当前范围

- 项目以个人开发、演示和本机运行方便为优先。
- 当前不考虑与其他开发者合并 SQLite 工作数据库，也不为多人协调额外设计公共表。
- 业务页面按已经确认的 23 个页面范围分阶段实现。

## 用户与角色

- 不实现真实登录、密码验证、身份认证和权限控制。
- 继续集中使用模拟用户 `zhang.zhuren`，显示名“张主任”。
- `sys_users`、`sys_roles`、`sys_user_roles` 只承担模拟业务中的操作人、评分人、上传人、复核人和角色展示。
- 业务模块通过 `CurrentUserService` 获取当前模拟用户，不得各自写死姓名或用户编号。
- 只有页面实际需要时才增加模拟用户、角色或关联数据，不继续扩展认证系统。
- `password_hash` 当前保持空值，不开发密码设置、登录会话、Token、权限菜单或接口鉴权。

## SQLite 与迁移

- `backend/database/权责清单.sqlite` 是本机工作数据库，不纳入 Git，也不因忽略规则而删除。
- 数据库结构通过独立版本 SQL 迁移维护；已执行的迁移不得修改、改名或删除。
- 权责数据通过原始 Excel 和 Python 导入脚本重建。
- 新业务表由页面实际需求驱动，不提前建设未使用的公共能力。

## 外部系统和智能能力

- 短信、12345、政务平台、组织部接口、RPA、NLP、OCR 和 AI 暂时只做本地模拟。
- 模拟功能必须明确标记数据来源和状态，不伪装成真实外部调用。
- 具体暂缓内容持续维护在 `docs/unfinished-features.md`。

## Git 工作规则

- 每个明确开发阶段完成后，先检查变更、运行相关测试并更新未完成功能清单。
- 每次提交只包含一个清晰主题，使用可读的中文提交信息。
- 验证通过后推送到 `origin/main`，禁止强制推送。
- 禁止提交本地数据库、构建产物、依赖缓存、日志、密钥、Token 和个人配置。
